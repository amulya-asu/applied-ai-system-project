# Quick Loom Recording Script (2-3 minutes)

**Copy this into a notepad while recording - just follow along!**

---

## Before You Click Record

1. ✅ Activate virtual environment: `.venv\Scripts\activate`
2. ✅ Start Streamlit: `streamlit run streamlit_app.py`
3. ✅ Close unnecessary browser tabs
4. ✅ Set Streamlit to default view (it will load automatically)

---

## Recording Script

### [0:00-0:15] Introduction (15 sec)
**Say:** 
> "Hi, this is my Social Music Recommender system for my Applied AI course. It extends my earlier music recommender with onboarding, friend recommendations, and built-in reliability testing. Let me show you how it works."

### [0:15-1:00] Existing User Demo (45 sec)
**Do:**
1. Click sidebar → "Existing user"
2. Select "Ava (u1)"

**Say:**
> "First, here's Ava, an established user. She has listening history and prefers pop and EDM with uplifting moods. The system generates personalized recommendations using her taste profile plus social signals from friends. You can see confidence scores and explanations for each song. Notice how the recommendations match her preferences."

**Point to:** Profile card → Top recommendation → Confidence score → One explanation

### [1:00-1:45] New User Onboarding (45 sec)
**Do:**
1. Click sidebar → "New user onboarding"
2. Select "Zara (u9)"

**Say:**
> "Now here's Zara, a new user who just joined through an invite. She has very little history, so we're in cold-start mode. The system shows a 4-step onboarding flow: she accepted an invite, added friends, entered starter preferences, and now gets recommendations. In this mode, the system relies more heavily on friend favorites and social recommendations to solve the cold-start problem."

**Point to:** 4-step walkthrough → Profile → "cold-start mode" in recommendations

### [1:45-2:15] Comparison View (30 sec)
**Do:**
1. Click sidebar → "Compare both"

**Say:**
> "Here's a side-by-side comparison. The existing user gets recommendations based primarily on personal history, while the new user gets recommendations weighted more toward social signals. Both have high confidence, but the reasoning differs."

**Point to:** Weight differences (P/S ratios)

### [2:15-2:30] Reliability Checks (15 sec)
**Do:**
1. Scroll to bottom "Reliability Summary"

**Say:**
> "Finally, the system includes integrated reliability checks. All 4 checks pass: new users get onboarding recommendations, established users get preference-aligned results, all friendships are valid, and all song references are correct."

### [2:30-2:45] Wrap-up (15 sec)
**Say:**
> "This demonstrates my reliability-focused AI feature. The system doesn't just make recommendations - it validates its own behavior every time it runs. Thanks for watching!"

## If You Get Nervous

**You don't need to say it perfectly!** Just:
- Show the 3 views
- Point out differences between existing/new users
- Show reliability checks at the bottom

The visual demo is what matters most. Your professor just needs to see it **actually running**.

## Backup Plan

If you mess up:
- Just re-record! Loom is free and unlimited
- Or just show the screens without talking (visual is enough)
- Or cut out the mistake in Loom's editor

You got this! 🎬
